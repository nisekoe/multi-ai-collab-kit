# 系统级选窗卡片（一种不绑定平台的确认方式）

> 问题：多平台协作里，经常需要用户从一堆会话里挑一个。各平台自带的交互能力不一样：有的能弹选项卡片，有的只能在聊天里问，有的只能报编号。用户通常只记得窗口名字，不记得编号。

## 一、思路

把「让用户选」从各平台里抽出来，做成一个**独立的本地小服务**：

- 任何一端要选窗，就往服务里发一条请求（标题 + 分组 + 选项）；
- 服务在屏幕右下角弹一张小卡片，用户点选；
- 结果写回服务，发起方来取。

这样谁都能用同一张卡，不依赖平台有没有卡片能力；编号留在工具层，用户只看见名字。

## 二、接口（只绑 127.0.0.1）

- `POST /api/request`：`{title, subtitle, groups:[{title, kind, q, options:[{label, description, tags, id}]}]}`
- `GET  /api/pending`：还有哪些没选
- `POST /api/answer`：`{id, choice}`（单选）或 `{id, choices:[...]}`（多问）
- `GET  /api/result?id=`：取结果

分组有两种用途：
- 同一个问题下的**分区**（例如「刚开的窗口」「项目」「会话区」），点一下即生效；
- 明确标了不同 `q` 的组，才算**多个问题**，要各自选完再点「确定」。

## 三、交互约定（实测后定下）

- 每组一个浅底面板，里面是白色卡片条；组头带类型徽标（项目 / 无分类对话）。
- 最近活跃的那条带橙色标记；新窗口单独置顶。
- 卡片 10 分钟没人理会自动过期收起，避免堆积。
- 弹出有淡入上浮，选中或关闭有淡出下沉。
- 悬停变手型，整行可点。

## 四、为什么不用各平台自带的能力

- 平台 A 的卡片只在它自己的会话里有效，换一端就没了；
- 平台 B 只能文字提问，用户不得不记编号；
- 维护三套交互，规则必然漂移。

统一到一个服务后，协作框架里只需要写「什么时候该问」，不用再写「每个平台怎么问」。

## 五、实现提示

参考实现是 Python + Tkinter（Windows），画布自绘圆角、Win32 设置圆角区域与投影，HTTP 服务跑在后台线程。不依赖第三方库。卡片样式与配色可按自己的品牌替换，接口不变。
